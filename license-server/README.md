# X5Agent License Server

Central licensing service for X5Agent. Separate deployment: this folder is never
shipped inside the client build and never copied into the desktop installer.

## Phase 1 scope (implemented)

- Accounts: self-serve signup, login, logout. **No email step** — an account is
  active the moment it is created (only email uniqueness is enforced), so the
  request returns a ready session and the trial starts immediately.
- Device binding: **last device wins** (one active device per subscription).
- Plans: trial is a normal plan (`is_trial`), can be disabled.
- Heartbeat: boot + every 10 minutes, 15-minute Ed25519 entitlement token.
- Server-side subscription time; no offline mode and no lease.
- Notices: generated by the server (no free-text admin messages); the client
  renders them with the agent template and forwards them through the gateway.
- Admin API + **admin web panel**: this server is the one central server, so its
  own UI lives at `/` (307 → `/admin`) and is split into sections — Overview,
  Accounts, Plans & pricing, Billing. Sign in, stats, search accounts, account
  detail (subscriptions + devices), warn, clear, suspend, extend, activate, plan
  list/create/enable/disable, **delete a plan** (refused with `409 plan_in_use`
  once any account or checkout used it — disable it instead, so history stays
  honest), and a read-only Billing view (`GET /v1/admin/billing`: totals + the
  latest checkout sessions). `/favicon.ico` answers `204` so browsers stop 404ing.
  Admin accounts are separate from customer accounts; the panel says so.
- Rate limiting: sliding window per client address for signup/login (10/min,
  admin login 5/min), heartbeat 60/min, admin API 120/min. Bounded in-memory
  state, per process.
- Passwords: Argon2id. Refresh tokens: random, stored as SHA-256 hashes.
- IP addresses: stored only as peppered hashes.

## Billing (Phase 3, implemented — sandbox provider)

- `POST /v1/billing/checkout` creates `checkout_sessions` row and returns the
  provider link; `POST /v1/billing/checkout/status` polls it (owner-only: a
  session that belongs to another account is `404`).
- `GET /v1/sandbox/session/<id>` and `POST /v1/sandbox/pay` are the provider
  callback, guarded by `X-Sandbox-Secret` (`secrets.compare_digest`).
- Completing twice is safe (the same subscription comes back). Buying the same
  plan again **extends** the running period; a different plan or a trial is
  replaced by the new one.
- Settings: `CHECKOUT_PROVIDER=sandbox`, `SANDBOX_PUBLIC_URL`,
  `SANDBOX_SHARED_SECRET`, `CHECKOUT_TTL_SECONDS` (default 1800),
  `CHECKOUT_RETURN_URL` (fallback only — the console sends its own).
- The provider itself lives in `../checkout-sandbox/` (separate deployment,
  port 8789). Dodo replaces only the checkout link and the callback.

## Local run (Windows)

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
# Edit .env and set ADMIN_BOOTSTRAP_EMAIL / ADMIN_BOOTSTRAP_PASSWORD for local admin access.
.\.venv\Scripts\python -m uvicorn app.main:app --reload --port 8787
```

Open http://127.0.0.1:8787/docs for the API explorer and
http://127.0.0.1:8787/admin for the admin panel.

## Tests

```powershell
.\.venv\Scripts\python -m pytest -q
```

Tests use a temporary SQLite database and temporary signing keys; they never
touch a real database or the real key files.

## Production

- `ENVIRONMENT=production`
- `DATABASE_URL=postgresql+psycopg://...`
- `JWT_SECRET` must be a real random secret (the app refuses to start otherwise).
- Put Caddy in front for TLS; bind the app to `127.0.0.1`.
- Back up the Postgres database and the `keys/` directory (encrypted).
- Never commit `.env` or `keys/`.

## Current test deployment (VPS)

- Code: `/opt/x5license` (system user `x5license`, venv at `.venv`).
- Service: `x5license.service` (systemd), port `8788`.
- Database: PostgreSQL 17, cluster `17/main`, `127.0.0.1:5433`, database
  `x5license` (the default `main` cluster moved to 5433 because Docker already
  owns 5432; nothing in Docker was touched).
- Health: `curl http://127.0.0.1:8788/v1/health`.
- Admin panel (the central server UI): `http://<server>:8788/` (redirects to `/admin`).
- Logs: `journalctl -u x5license -f`; restart: `systemctl restart x5license`.
- Change the admin password:
  `cd /opt/x5license && sudo -u x5license -H .venv/bin/python -m app.cli create-admin --email admin@x5agent.local --password 'NEW_PASSWORD'`.
- Backup: `pg_dump -p 5433 -U x5license x5license` plus `/opt/x5license/keys/`.

**Temporary:** this test deployment binds `0.0.0.0:8788` over plain HTTP so the
console/client can be tested from outside the VPS. Do not onboard real users
until it sits behind TLS (a domain + reverse proxy, or a Caddy vhost) and the
app is bound to `127.0.0.1`. Restrict `/docs` and the admin API at that point.

## Missing in this phase (next phases)

- Real Dodo Payments checkout + webhook (the sandbox stands in for it today).
- Admin 2FA (TOTP) and an audit log.
- Trusted-proxy handling (`X-Forwarded-For`) once TLS sits in front.
- Signed update manifests and repair packs.
- SMTP is intentionally out of scope: signup is self-activating by design.
